# AWSPricingCalculator_forTAE 仕様書

最終更新: 2026-10-03

## 1. 目的

AWS 上のシステム構成について、複数の構成案を同一画面で trial and error しながら比較し、月額概算を確認する Web アプリケーションを作る。

本アプリは、AWS Pricing Calculator のような「入力 → 保存 → 別画面へ遷移 → 出力」という操作ではなく、1つのワークスペース上で構成案の追加・複製・編集・比較を継続できることを重視する。

主な利用ケースは、ベンダー提案や既存設計に書かれた AWS サービス構成を入力し、その構成を複製・変更しながら代替案を比較することである。

---

## 2. データソースと料金計算の前提

### 2.1 データソース

料金計算の正本は **AWS Public Price List JSON のみ**とする。

為替レート、税率、外部価格 API 等の追加データソースは原則として使用しない。

### 2.2 固定条件

以下はユーザー選択項目ではなく、アプリの料金計算前提として固定する。

- Currency: USD
- Pricing: On-Demand
- Discount: None
- Tax: Not included

Savings Plans、Reserved Instances、Spot、税計算、為替換算は当面対象外とする。

### 2.3 Region

Project 全体の既定 Region を持つ。

初期値は `ap-northeast-1` (Tokyo) とする。

各 AWS リソースは Project Region を継承する。将来的に個別リソース単位で Region override を許容できる構造にするが、現モックでは Project Region の継承のみを表示している。

### 2.4 Price List の更新

画面上に、使用中の Price List データ日付を表示する。

復元 JSON には保存時点の Price List 日付を記録するが、復元後の金額はその時点で利用可能な Price List データを使って再計算することを基本とする。

## 3. 基本概念

### 3.1 Project

1つの見積検討単位。

Project は以下を持つ。

- Project 名
- Default Region
- 構成案一覧
- 差分比較の基準案
- 比較行

### 3.2 構成案（Plan / Variant）

1つのシステム構成案。

各案は独立した AWS サービス構成を持つ。

案ごとにサービスの種類や有無が異なってよい。

例:

- 案A: EC2 + RDS + S3 + ALB
- 案B: EC2 + Aurora + S3 + ALB
- 案C: Lambda + Aurora Serverless + S3 + API Gateway

構成案に「最小」「最大」「推奨」等の意味はアプリ側で付与しない。ユーザー自身が案名・メモで意味付けする。

### 3.3 比較行

比較表の1行を、特定の意味論的な「役割」ではなく、**ユーザーが同じ行で比較したい項目**として扱う。

そのため、Application / Database 等の役割名入力は必須にしない。

例:

- 案A: RDS
- 案B: Aurora

を同じ行に置いた場合、その行は `RDS / Aurora` として比較される。

比較行に異なる AWS サービスを設定することは可能とする。

## 4. 初回操作フロー

### 4.1 0案状態

新規 Project は構成案 0 件から開始できる。

このとき比較表の代わりに、以下を表示する。

- 「構成案はまだありません」
- 「最初の構成案を作る」
- 必要に応じてサンプル構成を表示する導線

### 4.2 最初の構成案作成

「最初の構成案を作る」を押すと、案Aを作成する。

初期状態の案Aには AWS サービスを含めない。

作成後、そのまま AWS サービス追加操作へ進める。

### 4.3 サービスを積み上げる

最初の案では、ベンダー提案等に書かれたサービスを上から順に追加するだけで構成を作れることを基本とする。

例:

1. EC2 を追加
2. RDS を追加
3. S3 を追加
4. ALB を追加
5. EBS を追加

最初から比較相手や役割名を考える必要はない。

---

## 5. AWS サービス追加

### 5.1 新しいサービスを追加

各構成案の末尾に「サービスを追加」操作を常設する。

この操作は、既存の比較行とは独立した **新しい比較行** を作成し、その案にだけサービスを追加する。

サービス選択後は、初期値を黙って確定せず、そのサービスの詳細パラメータ編集へ進む。

### 5.2 既存比較行に追加

ある比較行で特定案だけサービスが存在しない場合、空セルに「この行に追加」を表示する。

この操作は「新しい行を作る」のではなく、既存比較行へその案を参加させる操作とする。

### 5.3 別サービスに置換

複数案を比較している場合、同じ比較行の中で各案に異なる AWS サービスを設定できる。

各サービスセルに「別サービスに置換」を表示し、同じ比較行のまま AWS サービス種別を変更できる。

例:

- EC2 → Lambda
- RDS → Aurora

置換後も同じ比較行として扱う。

比較行の左ラベルは、その行で実際に使われているサービス名から自動生成する。

例:

- 全案 S3 の場合: `S3`
- RDS と Aurora が混在: `RDS / Aurora`
- EC2 と Lambda が混在: `EC2 / Lambda`

---

## 6. 構成案の操作

### 6.1 新しい案

「新しい案」で空の構成案を追加できる。

### 6.2 複製

任意の構成案を複製できる。

複製時は、その案に含まれるサービス構成とパラメータをコピーする。

基本利用では、最初の案を作成した後、それを複製して差分だけ変更する操作を主要フローとする。

### 6.3 削除

任意の構成案を削除できる。

削除時は確認を行う。

削除した案にしか存在しないサービス行は、全案から空になった時点で自動削除する。

差分基準案を削除した場合は、残っている先頭案を新しい基準案にする。

最後の1案だけになった場合は、その案の削除操作を表示しない。

---

## 7. サービス編集

サービスセルの「編集」から右側 Drawer を開く。

Drawer ではサービス固有のパラメータを編集する。

現モックで扱っている例:

- EC2 / RDS / Aurora
  - Instance type
  - Quantity
- S3 / EBS
  - Capacity (GB)
- Lambda / API Gateway
  - Requests / month
- Aurora Serverless
  - Average ACU
- その他モック項目
  - Monthly mock price

値を変更すると、そのサービス価格、構成案合計、基準案との差額を即時反映する。

---

## 8. 比較表示

複数の構成案を列として横並び表示する。

各行には以下を表示する。

- AWS サービス名
- 主な設定値
- 月額概算
- 編集操作
- 別サービスへの置換操作
- その案から外す操作

あるサービスがその案で使われていない場合は `—` を表示する。

各案の上部および表下部に月額合計を表示する。

ユーザーが選択した基準案との差額を各案に表示する。

## 9. 保存・復元

### 9.1 ブラウザ自動保存

編集中の Project 状態はブラウザの `localStorage` に自動保存する。

目的は、同じ PC・同じブラウザでページを閉じた後も作業を再開できるようにすることである。

ブラウザ保存は正式なバックアップとは扱わない。

### 9.2 復元 JSON

Project の編集状態を JSON として表現する。

最低限、以下を保存する。

- schemaVersion
- Project 名
- Default Region
- Baseline Plan ID
- Plans
- Comparison Rows
- 各サービスの設定値
- 保存日時
- Price List データ日付

Price List 本体は復元 JSON に含めない。

料金そのものを正本として保存せず、復元後は現在の Price List データから再計算する。

### 9.3 復元操作

社内環境でファイルアップロードが制限される可能性を考慮し、復元 JSON ファイルのアップロード UI は必須としない。

「状態を復元」を押すとテキスト入力欄を表示し、ユーザーが JSON ファイル内容をコピー & ペーストして「JSONを適用」する方式とする。

適用前に最低限以下を検証する。

- JSON として解析可能か
- schemaVersion が対応しているか
- Project Region が有効か
- Plan ID が不正・重複していないか
- 比較行形式が妥当か
- 未知のサービス ID が含まれていないか

適用すると現在の画面状態を置き換える。

## 10. 出力

### 10.1 PDF

最終的な見積結果は PDF で出力できるようにする。

### 10.2 PDF + 復元 JSON

PDF 出力時には、同じ操作で復元用 Project JSON も同時に出力する。

ユーザーに「別途保存操作」を要求せず、PDF と復元情報を一緒に残すことを基本 UX とする。

想定ファイル例:

- `web-renewal-estimate.pdf`
- `web-renewal-estimate.project.json`

現モックでは Project JSON のダウンロード後、ブラウザの印刷ダイアログを開く方式で PDF 出力動作を模擬している。

### 10.3 CSV

比較内容を表計算等で利用するための CSV 出力を用意する。

CSV は復元用途ではなく、人間・表計算ソフト向けの出力とする。

## 11. UI 方針

- 主要操作は1画面内で完結させる。
- 画面遷移を極力使わない。
- サービス編集は Drawer、追加・復元は Modal を基本とする。
- 案が1件の間は「構成入力画面」として自然に使え、2件以上になると同じ画面がそのまま比較表として機能することを目指す。
- 「新しいサービスを追加」と「既存比較行に追加」は明確に区別する。
- 比較のためだけに役割名やカテゴリ名をユーザーへ入力させない。
- ベンダー提案のサービス一覧を、そのまま順番に転記できることを優先する。

## 13. 現時点で未実装・今後の設計対象

以下は方針または必要性は認識しているが、実装仕様が未確定または未実装。

- AWS Public Price List JSON の取得・更新方式
- Price List JSON のローカル正規化・検索方式
- 各 AWS サービス固有の料金計算 adapter / resolver
- 実際の PDF レイアウト
- CSV の列構成
- 個別リソースの Region override
- 復元 JSON の将来 schema migration
- 保存時 Price List と現在 Price List が異なる場合の詳細 UI
- 大量サービス・大量構成案時のスクロール / レイアウト最適化
- AWS サービス追加 UI の検索・絞り込み

---

## 14. 非目標（現段階）

現段階では以下を目的としない。

- AWS アカウントへの接続
- 実リソースの自動検出
- CloudFormation / Terraform の生成
- RI / Savings Plans / Spot を含む最適化提案
- 税込み請求額の再現
- 為替換算
- AWS Pricing Calculator の完全互換

本アプリの主目的は、AWS 構成案を素早く作成・複製・変更し、料金差を同一画面で比較できることに置く。
